# OC2012 — invalid-generated-clock-transform

**Default severity:** error

**Category:** generated clocks

Reports malformed, conflicting, or ambiguous `create_generated_clock`
transform options. The static checks cover:

- exactly one positional target-collection argument, which may itself contain
  multiple ports, pins, or nets;
- selection of one transform mechanism from `-divide_by`, `-multiply_by`,
  `-edges`, or `-combinational`, with the supported `-combinational
  -divide_by 1` combination;
- positive integer divide/multiply values;
- `-duty_cycle` only with multiplication and in the inclusive range 0–100;
- exactly three positive, one-based, strictly increasing integer `-edges`
  values;
- one finite `-edge_shift` per generated edge and a strictly increasing shifted
  edge result;
- valid use of `-invert` and the required name/master fields for `-add`; and
- `-source` and `-master_clock` collections that contain exactly one collection
  occurrence. Duplicate or overlapping patterns remain non-singleton even when
  they collapse to one unique object.

Use one reviewable transform and make the source/master relationship explicit.
When a valid master is available, OpenConstraint derives the period for
divide/multiply/combinational transforms and derives the waveform for supported
duty-cycle or edge/edge-shift transforms. The normalized transform fields are
included in JSON and cross-mode comparison.

`OC2012` validates option shape and deterministic arithmetic. `OC2010` and
`OC2011` separately check source/master topology. None of these rules evaluates
Liberty timing arcs, gating conditions, case analysis, phase intent, or path
timing, and a non-finding is not sign-off certification.
