# OC3001 — input-delay-missing

**Default severity:** warning

**Category:** I/O

Reports input or inout ports that are not recognized clock sources and do not
have a finite, direction-valid `set_input_delay` whose clock reference is
absent or resolves in the current mode. A port is excluded as a clock source
only when it is targeted by a defined clock that reaches a sequential clock
pin.

Add interface-appropriate input delays, or document and model an intentional
asynchronous interface using the flow's timing policy. Merely adding a blanket
delay to silence the rule can conceal protocol mistakes.

The beta validates that the value is finite, the port direction is compatible,
and an explicit clock resolves. Separate diagnostics cover those failures,
min/max completeness, and replacement without `-add_delay`. It does not prove
the value, edge choice, or interface protocol is correct. Inout ports
participate in both input and output obligations.
