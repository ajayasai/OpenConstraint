# OC1004 — unsupported-query

**Default severity:** error

**Category:** queries

Reports a non-dynamic object query that the beta cannot resolve, such as an
invalid regular expression, an `-of_objects` source collection type rejected by
OpenSTA, or a filter outside the documented simple direction and
sequential-cell forms. It also reports missing, invalid, or command-mismatched
selector options; invalid positional arity; and valid OpenSTA qualifiers whose
semantics are not modeled by the static backend. Explicitly empty filter
expressions also fail closed instead of silently selecting the unfiltered
collection. Python-only regular-expression constructs, malformed Tcl pattern
lists, invalid Unicode escapes, and selector nesting beyond 64 levels also fail
closed here.

The accepted regexp grammar is intentionally conservative. Python/Tcl-specific
extensions, alphanumeric escapes, counted or modified/repeated quantifiers,
advanced bracket expressions, and non-ASCII `-nocase` evaluation are rejected
instead of being interpreted with backend-specific behavior. Patterns are
limited to 4,096 characters, 64 group levels, eight quantifiers, one unbounded
quantifier and one alternation per path component, no repetition alongside a
top-level component alternation, and 10,000,000 estimated
collection-comparison states. Globs use pinned UTF-8 byte semantics and are
limited to 1,000,000 states per comparison and 10,000,000 per collection walk.
Crossing a deterministic limit is unsupported rather than an empty match.

Escaped hierarchy dividers and bus-range-shaped patterns are also unsupported:
the flattened beta model cannot distinguish an escaped slash from a hierarchy
path or expand a range without declaration provenance. Use an unambiguous
modeled path and list exact bus bits explicitly.

Rewrite the query using the supported subset or provide a minimal synthetic
fixture in a compatibility request. Review every dependent constraint manually;
OpenConstraint does not guess the intended collection.

OC1004 is distinct from OC1001: unsupported means the resolver cannot determine
the answer, while zero-object-query means the supported resolver determined
that the answer is empty. An unsupported query forces the affected mode's
trusted aggregate coverage to `0.0/F`.
