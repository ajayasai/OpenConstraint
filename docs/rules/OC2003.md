# OC2003 — clock-redefined

**Default severity:** error

**Category:** clocks

Reports a clock name defined more than once without a clean additive merge.

The emitted severity is error when period or targets conflict and warning when
those fields agree but the duplicate is still not a valid merge. Use one
authoritative definition, or use `-add` only for an intentional additive target
merge. Evidence points to the prior definition.

A clean `-add` merge requires matching normalized period, waveform,
primary/generated classification, master, divide/multiply/duty, invert,
combinational, edge, and edge-shift fields. The beta does not fully reproduce
vendor command precedence or compare every clock property; source-path and
other unsupported properties still need review.
