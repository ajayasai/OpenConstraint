# OC3011 — io-delay-clock-reference

**Default severity:** error

**Category:** I/O

Reports the clock relationship of a modeled input/output delay when it needs
review:

- **note:** no `-clock` was supplied. Clockless I/O delay syntax is legal, but
  the launch/capture relationship is not explicit;
- **error:** `-clock` is dynamic, missing, or does not resolve to exactly one
  collection occurrence; or `-reference_pin` does not resolve to exactly one
  modeled port/pin occurrence. Duplicate or overlapping patterns remain
  non-singleton even when their unique-object set has size one. Literal
  references count the complete Tcl list and look up the original singleton
  spelling rather than flattening nested grouping.

Define the real or virtual clock before the delay and use a static clock name or
supported `get_clocks` query. An unresolved explicit clock reference does not
satisfy the input/output coverage obligation; an intentional clockless finite
delay can satisfy it and remains visible through the note.

This rule checks name/collection resolution and Tcl collection multiplicity. It
does not prove clock-edge, latency, phase, or interface-protocol correctness.
