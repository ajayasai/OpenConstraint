# OC1001 — zero-object-query

**Default severity:** error

**Category:** queries

Reports a supported static SDC object-query pattern that resolves successfully
but matches no object in its modeled universe. Each pattern is checked, so a
valid member of a multi-pattern query cannot mask a typo in another member.

An empty collection commonly makes the surrounding constraint ineffective.
Check spelling, hierarchy separators, synthesis renaming, top-module selection,
object kind, filters, and the netlist used for this mode. Evidence includes the
raw query, object kind, universe size, final matched count, and every unmatched
pattern. A query can therefore produce OC1001 while its combined collection is
nonempty.

OpenSTA ignores positional patterns when `-of_objects` is present, so those
words are not reported as misses. Patterns in the nested source selector are
audited independently.

For the source-pinned OpenSTA compatibility target, omitting the positional
pattern from `get_ports`, `get_pins`, `get_cells`, `get_nets`, or `get_clocks`
means the implicit wildcard `*`. That intentional compatibility behavior can
produce OC1002. An explicitly supplied empty Tcl word, such as
`[get_ports {}]`, remains an empty pattern and produces OC1001; it is never
widened to the whole object universe.

Dynamic and unsupported queries produce OC1003 or OC1004 instead. The rule can
only resolve objects represented by the documented structural parser subset;
a zero match caused by an unsupported netlist construct should be reduced and
reported as a compatibility issue.
