# OC6001 — opensta-validation-failed

**Default severity:** error

**Category:** OpenSTA

Reports that an explicitly requested OpenSTA validation mode timed out, exited
nonzero, failed `check_setup`, did not produce an effective SDC snapshot, or
produced a snapshot that exceeds 16 MiB (16,777,216 bytes) or is not valid
UTF-8. The static audit still completes and the diagnostic participates in the
normal `--fail-on` policy.

Evidence includes the captured OpenSTA version, return code, timeout flag,
failure reason, and bounded stdout/stderr tails. The report's
`summary.opensta` section also records per-mode duration, complete captured
output, and an effective-SDC SHA-256 only for a snapshot accepted within the
separate size and encoding boundary.

An oversized or invalidly encoded snapshot is rejected atomically: its text is
not retained, its SHA-256 is `null`, and `effective_audit` is not run. The
16 MiB limit is independent from the cumulative static-source budget and applies
after OpenSTA has executed the trusted SDC.

Review the OpenSTA output, input/library load, selected top, and `check_setup`
issues. Re-run with the same explicitly pinned executable and timeout. Never
enable `--opensta` on untrusted SDC: the file executes as Tcl with the caller's
permissions.

OC6001 says that this engine-backed load/check failed. Absence of OC6001 means
only that the separately installed OpenSTA process completed the adapter's
checks and wrote effective constraints; it is not timing sign-off or proof that
exceptions are functionally valid.
