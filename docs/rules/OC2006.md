# OC2006 — invalid-clock-definition

**Default severity:** error

**Category:** clocks

Reports a primary `create_clock` whose identity, target, or additive form is
structurally invalid. The rule fires when:

- neither `-name` nor a nonempty port/pin target identifies the clock;
- a supplied target collection is empty;
- a primary-clock target selector names an unsupported object kind; or
- `-add` is used without an explicit `-name`.

Give every virtual clock an explicit name. For a propagated primary clock,
resolve every supplied target to a modeled port or pin. Use `-add` only with an
explicit stable clock name so separate target definitions cannot be merged by
an inferred name.

This rule validates static command identity and target shape. `OC2001` and
`OC2005` separately validate period and waveform data, while `OC2003` reports
redefinition conflicts. OC2006 does not prove clock propagation, exclusivity,
or generated-clock relationships, and a clean result is not timing sign-off.
